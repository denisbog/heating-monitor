# monitoring-worker

Cloudflare Worker (Rust / `workers-rs` 0.8.7) that polls both heating clouds every
15 minutes, stores readings in D1, and serves a JSON API plus a static chart page.

Protocol research lives in `../docs/api-research.md`.

## Layout

```
src/lib.rs           entry points: #[event(scheduled)] + #[event(fetch)] /api/*
src/http.rs          outbound POST/GET helpers (RequestInit + Fetch)
src/model.rs         shared Reading / Device types
src/iletcomfort.rs   Dollin cloud client, C3/ATW frame decode, iBUILDING energy stats
src/cameconnect.rs   CAME Connect: OAuth2+PKCE, thermo.cameconnect.net, statistics
src/db.rs            D1 writes + read queries
schema.sql           D1 tables: devices, readings, runs, tokens
wrangler.toml        cron */15, D1 binding, static assets
assets/index.html    app shell (charts, token, controls)
assets/sw.js         service worker
assets/manifest.webmanifest  PWA manifest
assets/icon-*.png    app icons (generated by make-icons.py)
make-icons.py        regenerates the icons with Pillow
make-dev-vars.sh     builds .dev.vars from ~/.config/monitoring/credentials.toml
set-secrets.sh       pushes every .dev.vars entry as an encrypted Worker secret
```

## API access levels

Two bearer tokens, both passed as `Authorization: Bearer <token>`:

| token | secret | can |
|---|---|---|
| `API_TOKEN` | long random (generated) | read **and** `POST /api/collect` |
| `READ_TOKEN` | `1013` (deliberately simple, shareable) | read only — `POST /api/collect` returns **403** |

Every GET endpoint (`/api/health`, `/api/devices`, `/api/latest`, `/api/readings`,
`/api/daily`, `/api/runs`) accepts either token. Missing or wrong → `401`;
read-only token on `/api/collect` → `403 read-only token: collection not permitted`.

The chart page stores whatever token you paste and surfaces the 403 inline if you press
**Collect now** with the read-only one. `READ_TOKEN` defaults to `1013`; override with the
`READ_TOKEN` environment variable when running `make-dev-vars.sh`.

## PWA

`assets/` is an installable Progressive Web App:

| file | purpose |
|---|---|
| `index.html` | app shell — charts, token field, range controls |
| `manifest.webmanifest` | `standalone` display, `theme_color`, 3 icons |
| `sw.js` | service worker |
| `icon-192.png` / `icon-512.png` | any-purpose icons |
| `icon-maskable-512.png` | Android adaptive icon (28% inset, survives circular crop) |
| `apple-touch-icon.png` | 180×180, opaque, for iOS |

Icons are drawn with Pillow, so there is no SVG-delegate dependency and the result is
reproducible. Regenerate after changing the design:

```bash
python3 make-icons.py
```

Service-worker strategy:

- the shell is **precached** on install, so repeat loads are instant and it opens offline
- **navigations are network-first** → a deploy is picked up as soon as you are online
- other static assets are **stale-while-revalidate**
- **`/api/*` is never cached.** This is live sensor data; showing a stale reading as though it
  were current is worse than showing an error. Offline you get the shell plus
  "Offline — showing the cached page; live data unavailable."

Cache name is `v1-shell`. Bump `VERSION` in `sw.js` only when the precache *list* changes —
the HTML refreshes on its own because navigations go to the network first.

Install: Chrome/Android → ⋮ → *Install app*. iOS Safari → Share → *Add to Home Screen*.

## Build

```bash
cargo check --target wasm32-unknown-unknown   # fast local check
worker-build --release                        # produces build/index.js + index.wasm
```

Measured: **328 KB wasm (119 KiB gzipped)** + 24 KB js — comfortably inside the
64 MiB limit and under the ~1 MiB gzipped cold-start guideline.
Free plan allows 10 ms CPU per cron run; if a live run exceeds it, the $5/mo
Paid plan raises it to 30 s.

## Deploy

```bash
wrangler d1 create monitoring          # then paste database_id into wrangler.toml
wrangler d1 execute monitoring --file=schema.sql --remote

wrangler secret put ILETCOMFORT_USERNAME
wrangler secret put ILETCOMFORT_PASSWORD
wrangler secret put CAMECONNECT_USERNAME
wrangler secret put CAMECONNECT_PASSWORD
wrangler secret put CAMECONNECT_CLIENT_ID
wrangler secret put CAMECONNECT_CLIENT_SECRET
wrangler secret put API_TOKEN
wrangler secret put READ_TOKEN        # the shareable read-only token

wrangler deploy
```

Local development uses `.dev.vars` (gitignored), same key names.

## Known constraints

- **iLetComfort allows one session per account.** Every login signs the phone app
  out. Prefer a second account with the heat pump shared to it; see
  `../docs/api-research.md` ("login war").
- **CAME TH/700 has no server-side room-temperature history.** The 15-minute poll
  is the data source; we roll our own daily aggregates.
- The C3 sensor frame on this heat pump is a known placeholder — no water
  in/out, outdoor ambient, or compressor data via that path.
- The "Ambient T average" shown in the app is not yet extracted.
